# 发文章教程

在自己的电脑上编辑文章，通过 HTTPS Git 推送到博客。这篇文章和「开发进度」由安装程序放入站长的个人仓库，站长可以直接修改、更新或撤回。

## 1. 准备账户和发布权限

安装 Git，然后在本站[注册或登录](/login)。普通注册账户需要联系站长获得发布权限，再到[账户与发布](/account)查看自己的权限和仓库地址。站长已具备发布权限。

Git 使用网站用户名和密码验证身份，与浏览器登录分别验证。无需 SSH 公钥，也无需自己创建服务器裸仓库。

## 2. 克隆个人文章仓库

将 BLOG_HOST 替换为本站域名，或者直接使用账户页给出的仓库地址：

```sh
git clone https://BLOG_HOST/git/content.git my-articles
cd my-articles
```

按提示输入网站用户名和密码。所有作者使用同一个地址，服务器按账号分配独立仓库，其他作者不能克隆你的内容。站长首次克隆时已包含两篇内置文章；其他作者可能得到空仓库，空仓库提示属于正常情况。

如果这是空仓库，将本地分支设置为 main：

```sh
git switch -C main
```

需要保存凭据时使用操作系统的安全凭据管理器。不要把密码写入地址或提交到仓库；credential.helper store 默认明文保存密码。保持 HTTPS 证书验证开启。

## 3. 登记文章与正文入口

每篇文章在根目录 index.toml 中对应一个条目。已有内容时，在原索引末尾追加，保留其他文章：

```toml
[[articles]]
id = "first"
folder = "posts/first"
title = "第一篇文章"
description = "记录一次新的开始。"
tags = ["随笔"]
public = true
# cover = "cover.png"
# entry = "main.md"
```

id 是作者仓库内的唯一文章标识，建议发布后保持不变。使用小写英文字母、数字和中间短横线，最多 40 位。folder 为 posts 下的独立文章目录，不与其他条目重复。标题必填，简介和标签可以省略。

正文默认读取该目录的 main.md，也可以用 entry 指定其他入口。封面可选，填写同文章目录中的图片文件名。作者、创建时间和修改时间由系统记录，不需要写入索引。不要添加日期、作者或精华等未开放字段。

public 只有设为 true 才会公开。省略或设为 false 后，公共页面无法阅读；登录后阅读内部文章的功能尚未开放。

创建 posts/first/main.md：

```markdown
# 第一篇文章

你好，这是我的第一篇文章。

[阅读第二页](chapter.md)
```

如果只需要一页，删除第二页链接。如果需要第二页，再创建 posts/first/chapter.md：

```markdown
# 第二页

这里继续写正文。

[返回入口](main.md)
```

页面之间使用同目录相对链接，可以带锚点。不要使用子目录或上级目录引用。只有从入口可以通过链接到达的页面才会发布，图片需要在正文引用或设为封面。未登记的目录不会发布。

## 4. 提交与发布

在仓库目录执行：

```sh
git add index.toml posts/first
git commit -m "发布第一篇文章"
git push -u origin main
```

第一次使用 Git 时，如提示缺少提交者信息，按 Git 的提示设置姓名和邮箱。认证身份由网站账号决定，不能靠提交中的姓名冒充其他作者。

每次推送只接受一个新提交，必须直接接续远端 main；空仓库的第一次提交必须是根提交。不接受 merge、强制推送、标签或其他分支。

等待后台同步后，到[文章列表](/articles)查看标题，并检查正文、图片和多页链接。Git 接收成功不等于文章已经公开，索引有问题时会暂存提交，保留上一次发布版本，等待修复。

## 5. 更新与撤回

每次开始写作前拉取远端最新版本。修改完成后，整理为一次提交：

```sh
git pull --ff-only
# 修改正文或 index.toml 后执行：
git add index.toml posts/first
git commit -m "更新文章"
git push
```

多台电脑同时写作时，先解决冲突并整理尚未推送的提交，不要使用强制推送。

撤回一篇文章时，删除对应的整个索引条目，再提交推送即可。撤回全部文章时，把 index.toml 明确写成：

```toml
articles = []
```

不要通过删除或清空索引来撤回全部文章。错误或缺失的索引会保留原版本；有效索引指向的入口缺失时，该篇文章会被撤回。撤回不会擦除 Git 历史或已经克隆的内容。内置文章也遵循相同规则，不会在重启后自动恢复。

## 文件限制与常见问题

仓库只允许根目录 index.toml，以及文章目录内的小写扩展名 .md、.markdown、.txt、.png、.jpg、.jpeg、.webp 普通文件。不提交 .gitignore、证书、脚本、HTML 或编辑器配置。正文禁用原始 HTML、危险链接、外链图片和脚本。

索引最多 64 KiB，每篇文章最多 64 个可达页面；单个文本最多 256 KiB，图片最多 2 MiB，单次 Git pack 最多 8 MiB。所有文件都受安全检查，即使未登记或未被正文引用，也不能用来存放违规内容。

推送被拒绝时，先按终端提示修正。如果远端没有接收这次提交，用 git add 后执行下面的命令修改原提交，避免累积多个未推送的提交：

```sh
git commit --amend --no-edit
git push
```

推送成功但内容没变化时，检查 TOML 语法、字段名、公开设置、入口和相对链接目标。修复后创建一个新提交再推送。仍未更新时，请站长查看账户页中的暂存或同步状态。

无法克隆或推送时，检查用户名、密码和发布权限；改密后更新凭据管理器里的旧密码。数据库暂时不可用时，身份验证与推送会暂停，但已导入的公共文章仍可阅读。
